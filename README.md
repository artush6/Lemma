# Lemma

A mathematical study workspace with rich notes, equations, graphs, PDF/document tabs, Code Lab and flashcards. Built with React, TypeScript and TanStack Start; the editor uses TipTap and plain CSS.

## Local development

Use Node.js 22 and Bun 1.3.14 (the version used in CI). Keep `bun.lock` as the single committed dependency lockfile.

```sh
bun install --frozen-lockfile
cp .env.example .env.local
# Set the public Supabase URL and publishable key in .env.local.
bun run dev
```

Supabase Auth and the recorded database schema are required for the authenticated workspace. Recovery drafts do not constitute a separate guest mode. Do not put service-role keys in browser-prefixed environment variables.

## Checks

```sh
bun run check:unused
bun run test
bun run typecheck
bun run lint
bun run format:check
bun run build
```

`check:unused` follows static imports, re-exports, type imports and literal dynamic imports from framework entrypoints and tests. It respects Git's ignore rules, including local browser fixtures. Review runtime/config references before removing anything it flags; the check does not establish that a dependency or CSS selector is unused.

Lint and formatting exclude generated builds and local verification output. Existing lint findings in the ported editor are recorded in the cleanup changelog; they have not been hidden by weakening rules. GitHub Actions checks formatting, source reachability, types, unit tests and a production build using placeholder public configuration. Full lint remains a local check until its existing findings are addressed. CI does not test live authentication or database authorization.

## Branches and maintenance

`master` is the integration branch. Start short-lived `codex/<task>` branches from current `master`, keep each change focused, and merge tested changes back without rewriting published history. See the [branch inventory](docs/engineering/BRANCHES.md) for existing branch contents and retirement criteria.

Keep dependency updates separate from code removal. Use Bun 1.3.14 to update the manifest and lockfile together, keep TipTap versions aligned, and run the checks above before merging. Do not treat a successful build as evidence that live auth, cloud persistence or deployment works.

## Workspace and storage

Open notes, documents, Code Lab or Flashcards with a pane's + menu. Drag tabs to a pane edge to split, or right-click tabs for move/close options. The existing-document picker is centered and targets the pane where it was opened. A second view of the same note is read-only.

Notes, folders, versions and shared links use Supabase. Recovery drafts and workspace layout are device-local. Files opened directly as workspace tabs are cached locally; files inserted into notes follow note storage/history/sharing. Code Lab and flashcards are device-local. See the [data inventory](docs/engineering/DATA_INVENTORY.md) for details and known limitations.

## Smart paste

Paste LaTeX or Markdown into the editor to import headings, paragraphs, lists, quotes, code and mathematical equations. Math supports `$…$`, `$$…$$`, `\\(…\\)`, `\\[…\\]` and common equation environments. Local TeX math macros are kept with equations; unsupported body commands remain visible to avoid silent content loss. Imports use Lemma's editable layout rather than reproducing TeX package/font/page geometry.

## Why Lovable remains

This repository is connected to Lovable. These are active integrations, not decorative scaffolding:

- `@lovable.dev/vite-tanstack-config` supplies the React, TanStack, Tailwind, alias/env and Nitro build setup. Replacing it requires a deliberate build migration.
- `@lovable.dev/cloud-auth-js` and `src/integrations/lovable/` handle the existing Google OAuth flow.
- Supabase preview storage brokers sessions on recognized Lovable preview origins; optional error hooks report preview failures to the editor.
- Pushed commits sync back to Lovable. Preserve published Git history; do not force-push or rewrite pushed commits.

Generic template marketing and social attribution are not required for those integrations.

## Deployment

`vercel.json` selects TanStack Start and the Vite wrapper configures Nitro's Vercel preset. Use the existing Git integration for deployments; a successful local build is not deployment verification.

Set `VITE_SUPABASE_URL` and `VITE_SUPABASE_PUBLISHABLE_KEY`. The build retains compatibility with the existing `NEXT_PUBLIC_SUPABASE_URL` / `SUPABASE_URL` and `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` / `SUPABASE_PUBLISHABLE_KEY` names. Only the public URL and publishable key are bundled into the frontend. Server authentication helpers use unprefixed server configuration.
